# 01 — Business context

## What Master Batch Mixing is (shop floor)

A Master Batch (MB) is a colour or additive concentrate that gets blended
later into a Final Batch (FB) to make production compound. MB Mixing
happens on a **Two-Roll Mixing Mill** workstation. An operator with the
"Mixing Operator" role:

1. Weighs out raw materials (typically polymer base + colour/additive
   pigments + chemicals) according to a BOM
2. Loads them onto the mill, runs the mix for a defined cycle
3. Discharges the produced MB compound
4. Scans / enters the result into the Console Dash, where a **mix barcode**
   (`C_YYMMDDXn` format) is generated to identify the MB lot

Downstream consumers of an MB lot:
- **Compound Inspection** — QA samples the MB and runs spec tests (visual,
  hardness, viscosity, etc.)
- **Final Batch Mixing** — consumes the MB lot + additional raw materials to
  produce a production-ready compound
- **Sheeting** — turns FB compound into sheets that are then cut into clips

## Why this is process #1 in the porting chain

The full production chain that ends at Moulding Production Entry is:

```
Master Batch Mixing → Compound Inspection → Final Batch Mixing
  → Sheeting → Cut Bit Transfer → Bulk Clip Release → Blanking
  → Blank Bin Inward → Work Planning → Blank Bin Issue
  → Inspection Entry (Line/Patrol/Lot) → Moulding Production Entry
```

MB Mixing is the **head of the chain** — without an MB record, Compound
Inspection has no compound to inspect, FB Mixing has no MB to consume, and
every downstream process is starved. Therefore:

- Porting MB Mixing first was the smallest-blast-radius starting point
- Bugs here cascade into the entire downstream chain (the 6-strategy SE
  lookup in `sync_api.py::_lookup_legacy_stock_entry` exists specifically
  because legacy Compound Inspection needs to find this MB's manufacturing
  Stock Entry — see `04-bridge-layer.md`)

## What success looks like for the operator

1. Operator scans their employee badge → operator selected
2. Selects produced item (a Master Batch finished item) → BOM auto-loaded
3. Scans each raw material's barcode → batch verified against BOM, qty
   captured automatically
4. Enters produced quantity in Kg
5. Hits **SUBMIT TO ERP**
6. Sees a real-time status panel (Ops + Legacy each independently moving
   through `Pending → Processing → Success`) within seconds
7. Sees the generated mix barcode displayed on screen — also rendered as
   a printable label

## What success looks like upstream (Console reviewer / Hermes "Verified")

1. `Console Master Batch Mixing` row exists with `sync_status = "Success"`
   and `docstatus = 1`
2. `Console Transaction Log` has two entries (one per target leg), both
   `Status = "Success"`
3. Legacy bench `sppmaster.frappe.cloud` has a corresponding
   `Delivery Challan Receipt` with the same `reference_id` in `dc_no`, a
   submitted manufacturing Stock Entry behind it, and the
   `bridge_mix_barcode` set to the Console-generated value
4. Ops bench `newspp.m.frappe.cloud` has the corresponding `Stock Entry`
   (Manufacture) with the produced item in the target warehouse and
   consumed raw materials reduced from their source warehouses
5. The Stock Ledger reconciles on both ERPs

## Operational constraints

| Constraint | Reason |
|---|---|
| Operator must have role "Mixing Operator" | Dash enforces this via `validateRole` on operator scan; backend re-checks via `get_available_employees` |
| BOM must exist for the produced item | Dash hard-fails if `get_bom_for_produced_item` returns nothing |
| Backdating only for System Manager / Administrator | Regular operators are clamped to "today or yesterday" — System Manager can set arbitrary `posting_date` |
| Mix barcode generated by Console (not legacy) | Single source of truth — see `bridge_mix_barcode` in `04-bridge-layer.md` |
| Mass balance NOT enforced | Plan-doc called for `\|consumed − produced\| < 0.5%` check; intentionally not implemented (see `10-risks-and-decisions.md`) |

## Who interacts with this process

| Role | What they do |
|---|---|
| Mixing Operator | Runs the Dash submission |
| Quality Inspector | Inspects the resulting MB lot (next stage: Compound Inspection) |
| Quality Manager | Reviews rejected lots; signs off on deviations |
| System Manager / Administrator | Can backdate posting time for late-entered submissions |
