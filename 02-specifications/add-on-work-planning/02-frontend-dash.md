# 02 — Frontend (Dash) — `AddOnWorkPlanningEntry.tsx` (planned)

## Planned flow

```
Open AOWP screen
   │
   ▼
Scan Production Supervisor badge
   │
   ▼
Select posting_date, shift_type (Morning / Afternoon / Night)
   │
   ▼
For each item to plan:
   ├─► Click "+ Add Row"
   ├─► SearchableSelect Produced Item → BOM auto-fetches
   ├─► SearchableSelect Workstation → check for Mixing Operation override
   ├─► SearchableSelect Mould (optional)
   ├─► Enter target_qty → check against Work Plan Item Target (10% drift warning if applicable)
   ▼
Click Submit
   ├─► initializeSubmission({ payload })  ← generates Lot # before submit
   ├─► Promise.all per target
   └─► Success modal with generated Lot # + Job Card list (printable)
```

## Workstation override transparency UX

When `get_workstation_override` returns a different workstation than what the operator selected, the Dash MUST surface:

> ⚠ "This row's workstation will be set to **<master-data-workstation>** on Legacy (per Mixing Operation configuration)."

Banner visible BEFORE submit. Operator can keep selection (workstation will be overridden silently downstream).

## Target drift warning

```tsx
const checkDrift = async (row) => {
  const target = await getWorkPlanItemTarget({item: row.item_produced, shift_type: shiftType})
  if (target && Math.abs(row.target_qty - target.target_qty) / target.target_qty > 0.10) {
    setDriftWarnings({...driftWarnings, [rowIndex]: true})
  }
}
```

Visible inline next to the row: "Target qty drifts > 10% from shift target (<N>)".
